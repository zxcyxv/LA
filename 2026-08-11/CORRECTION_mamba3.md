# 정정 — `mamba3_ref.py` 의 감쇠가 죽어 있었다

> **한 줄.** 연산자 우선순위 실수로 `A` 가 상수가 되어, Mamba-3 재현본이
> **"아무것도 잊지 않고 미세하게 증폭하는 순수 누적기"** 로 돌아가고 있었다.
> **Mamba-3 와의 모든 대조가 무효다.**
>
> 발견 경위: 2026-08-11, 사용자가 "어제 mamba3 구현오류를 고치다가 접었던 것 같다" 고
> 지목 → git 확인 결과 수정이 커밋된 적 없음 → 코드 정독으로 재발견 → 공식 구현 대조로 확정.

## 1. 버그

```python
_A = -heavy_tail(dd_A.float()).clamp(max=-cfg.A_floor)      # 버그
_A = (-heavy_tail(dd_A.float())).clamp(max=-cfg.A_floor)    # 수정
```

파이썬에서 **단항 마이너스는 메서드 호출보다 느슨하게 묶인다.** 따라서 위 줄은
`-( heavy_tail(x).clamp(max=-A_floor) )` 로 해석되고, `clamp` 가 **먼저** 걸린다.

`heavy_tail` 은 정의상 **항상 양수**다.

```
f(x) = 1 + x        (x ≥ 0)   →  ≥ 1
     = 1 / (1 − x)  (x < 0)   →  ∈ (0, 1]
```

양수를 `clamp(max=-1e-4)` 하면 **전 원소가 정확히 `-1e-4`** 가 된다. 부호를 뒤집으면

```
A ≡ +A_floor = +1e-4      (상수, 그리고 양수)
```

### 1.1 실측

| | `A` 의 고유값 개수 (무작위 입력 10만) | 범위 |
|---|---:|---|
| **버그** | **1** | `[+1.0e-4, +1.0e-4]` |
| 수정 | 99,868 | `[−14.688, −7.13e-2]` |

### 1.2 귀결 둘

**① 입력 의존 감쇠가 통째로 죽는다.** `Δ_t A_t` 는 Mamba-3 의 간판 기능이고
`RESULTS.md §6.2` 가 우리와의 핵심 차이(`Mamba-3: 입력 의존 Δ_t A_t` vs `우리: 고정 α`)
로 지목한 바로 그 항이다. `DT` 쪽 입력 의존성만 남는다.

**② 부호가 뒤집혀 감쇠가 아니라 증폭이 된다.**

| | `decay = exp(ADT)` | `τ = 1/\|A·DT\|` 중앙값 |
|---|---|---:|
| **버그** | **1.000026 ( > 1 )** | **1,076,674 토큰** |
| 수정 | 0.999718 ( < 1 ) | **105.6 토큰** |

학습 길이가 `T=68` 이므로 `τ ≈ 106` 은 합리적 운용점이고, `τ ≈ 10⁶` 은 **망각 없음**이다.

## 2. 공식 구현 대조 — 확정

`state-spaces/mamba`, `mamba_ssm/modules/mamba3.py`:

```python
_A = -heavy_tail_activation(dd_A.to(torch.float32))
_A = torch.clamp(_A, max=-self.A_floor)
```

**두 문장으로 나뉘어 있다.** 공식 주석: *"This ensures the matrix remains negative
**after the negation operator**, with the A_floor parameter setting a lower bound on
magnitude."*

재현본이 한 줄로 합치면서 순서가 뒤집혔다. **재현본의 docstring 자체가 올바른 순서를
적어놓았는데**(`_A = -heavy_tail(dd_A), clamp(max=-A_floor)`) 코드가 그것을 따르지 않았다.

## 4. 무효화되는 결과

**전부 재측정이 필요하다.** 체크포인트가 `.gitignore` 되어 있어 재학습해야 한다.

### 4.1 `EXTRAPOLATION.md §6-3` — Mamba-3 외삽 대조 **전체**

| l_noise | 32 | 64 | 96 | 128 | 192 | 256 |
|---|---|---|---|---|---|---|
| Mamba-3(ref) 637k | 0.770 | 1.000 | 1.000 | 0.062 | 0.000 | 0.000 |
| ordinal 27k | 0.996 | 1.000 | 0.973 | 0.973 | 0.613 | 0.285 |

이 표의 Mamba-3 행은 **망각이 없는 모델**에서 나왔다. 간섭이 무한정 쌓이므로
긴 시퀀스에서 붕괴하는 것이 당연하다.

> **버그가 Mamba-3 를 실제보다 나쁘게 만들었다.** 따라서
> *"같은 동적 RoPE 인데 23배 파라미터로 훨씬 못한다"* 는 결론과
> *"우리는 우아하게 열화하고 Mamba-3 는 파국적으로 붕괴한다"* 는 서술을
> **모두 철회해야 한다.**

**그리고 그 문서가 설명하지 못하고 남겨둔 이상 징후 두 개가 이것으로 설명된다.**

| 문서의 관찰 | 버그로 설명되는가 |
|---|---|
| *"학습 길이보다 **짧은** `l_noise=32` 에서도 0.770. 위상 드리프트라면 긴 쪽만 나빠져야 하는데 양쪽이 나쁘다"* | **설명됨.** 증폭하는 상태는 길이와 무관하게 불안정하다 |
| *"192 와 256 의 수치가 소수점까지 같다 — 입력과 무관하게 같은 것을 내는 완전 포화"* | **설명됨.** 망각 없는 누적은 포화한다 |

§6-3 이 원인 후보로 적은 세 가지 중 **"입력 의존 감쇠의 포화"** 가 가장 근접했다.
포화가 아니라 **부재**였다.

### 4.2 `RESULTS.md §7` — "Mamba-3 가 같은 위상 코드를 학습한다"

위상 경로(`ang → tanh → ×DT×π → cumsum`)는 `A` 와 **독립**이므로 메커니즘 자체는
살아남을 수 있다. 그러나 §7.1 의 "8/8 채널이 주소 채널", §7.2 의 증분 프로파일,
§7.3 의 "깊이↔위상 교환 독립 재현" 은 **모두 감쇠가 없는 모델에서 나온 결과**다.

> `RESULTS.md §0` 요약의 **"Mamba-3(ICLR 2026)가 같은 위상 코드를 학습함 | 확정"**
> 을 **미검증**으로 내려야 한다.

특히 §7.3 의 "L=4 에서 주소 채널이 6/32 로 줄고 전부 layer 0 에 있다" 는
**층간 정보 흐름**에 관한 주장인데, 감쇠가 없으면 층별 역할 분담이 달라질 수 있다.

### 4.3 `CAPACITY.md §2·§5` — 파라미터 효율 곡선

`charlm.py` 도 이 구현을 쓴다. **이쪽은 방향이 반대다.**

> 버그로 불구가 된 Mamba-3 에게도 우리가 **졌다.** 따라서
> *"Model 1 은 파라미터 효율 곡선에서 Mamba-3 에 진다"* 는 결론은 유지되거나
> **더 나빠질 가능성이 높다.** 우리 열세가 **과소평가**됐을 수 있다.

`§6.1` 의 *"Mamba-3 는 `A_floor` 로 감쇠를 강제하므로 구조적으로 못 한다"* 는
서술은 `A_floor` 의 역할 자체에 대한 것이므로 **살아남는다** (공식도 같은 하한을 건다).

### 4.4 같은 날의 `diag_vs_mamba3.py [M3]`

τ 중앙값 108만을 **"초기화 선택"** 이라고 진단했다. **틀렸다. 버그의 출력이었다.**
같은 절의 `B_bias/C_bias = ones` 로 인한 내용 무판별 진단은 **버그와 무관하게 유효**하다
(다만 그것이 공식과 같은 초기화인지는 확인하지 않았다).

## 5. 왜 안 잡혔나 — 검사의 사각지대

우리 모델에는 `check_model0.py` / `check_model1.py` 가 있고 `parallel ≡ recurrent`
등가성을 **3.1e-15** 로 검증한다. **`mamba3_ref.py` 에는 그런 검사가 없었다.**

그리고 **이 버그는 등가성 검사로도 안 잡힌다** — 병렬 경로와 순차 경로가 *똑같이
틀린* `A` 를 쓰기 때문이다 (실제로 수정 전에도 상대오차 6.9e-07 로 일치했다).

잡으려면 **불변량 검사**가 필요했다.

| 잡을 수 있었던 검사 | 왜 |
|---|---|
| `A` 가 입력에 의존하는가 (고유값 개수 > 1) | 상수화를 직접 잡는다 |
| `decay = exp(ADT) < 1` 인가 | 부호 뒤집힘을 잡는다 |
| `τ` 가 태스크 길이와 같은 자릿수인가 | `10⁶` 은 명백히 이상하다 |

**세 번째는 같은 날 내가 실제로 관측하고도 넘어갔다** — `diag_vs_mamba3.py [M3]` 에서
τ = 108만을 재고 "A_floor=1e-4, DT∈[1e-3,1e-1] 이므로 |A·DT| ~ 1e-6" 이라고
**계산이 맞는다고 확인까지 하고** 초기화 선택으로 결론냈다.

> **이상한 값을 보고 "왜 이런 값이 나오는지" 를 설명하는 데 성공하면 거기서 멈추게 된다.**
> 설명이 됐다는 것과 그 값이 옳다는 것은 다르다. `EXCITABILITY.md` 가 기록한
> "찾으려는 대상을 검사 설계가 미리 지워버린다" 와 같은 부류의 함정이다.

## 7. 한계

- 재현본은 여전히 공식 구현이 아니다. `expand=1`, exponential-Euler only, MIMO 없음,
  그리고 `inc = tanh(ang)·DT.mean(-1)·π` 로 **헤드 평균 DT** 를 쓰는 근사가 있다
  (공식은 헤드별). 이 근사는 코드에 명시돼 있으나 영향은 측정되지 않았다.
- `B_bias`, `C_bias` 를 `ones` 로 초기화하는 것이 공식과 같은지 **확인하지 않았다.**
  같은 날 측정에서 이것이 초기화 시점 커널의 99.2% 를 상수항으로 채운다는 것을 봤다.
- 파라미터 23배 차이(637k vs 27k)라 "구조 덕분"과 "용량 탓"은 여전히 안 갈린다.
  `EXTRAPOLATION.md §6-3` 의 한계 절이 지적한 층수 정합 대조가 아직 없다.
